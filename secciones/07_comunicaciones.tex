\subsection{Topología y flujo de información}

{La arquitectura de comunicaciones se organiza en dos niveles. En el nivel de control, el PLC Siemens S7-1200 CPU 1214C se encarga directamente de la adquisición de datos de los sensores y del accionamiento de los actuadores, y se comunica con el panel HMI KTP700 Basic PN mediante PROFINET sobre Ethernet industrial, a través del switch Siemens CSM1277. En el nivel de supervisión, una Raspberry Pi con Node-RED lee las variables del PLC mediante el protocolo S7 y las envía por HTTP a una API desarrollada con FastAPI y desplegada en Amazon Web Services (AWS), desde donde las consume una interfaz web desarrollada en Streamlit. El diagrama de esta arquitectura y su estado de implementación se presentan en la Sección~\ref{sec:montaje_comunicaciones} (Figura~\ref{fig:arquitectura_iot}), y la propuesta completa, en el Anexo~\ref{anx:arquitectura_com}. Esta arquitectura reemplaza la propuesta del primer corte, basada en un router, un gateway ESP32 con módulo SIM y comunicación Modbus TCP y MQTT. La disposición adoptada permite mantener al PLC como elemento principal para el control y procesamiento de las variables del proceso, mientras que la Raspberry Pi funciona como una pasarela (\textit{gateway}) de comunicación entre la red de control y los servicios externos. De esta manera, se evita establecer una conexión directa entre el PLC e Internet, manteniendo separadas las funciones de control industrial y comunicación con la nube. Esta separación contribuye a mejorar la seguridad de la arquitectura de comunicaciones, aspecto relevante en sistemas industriales conectados, debido a los riesgos asociados con la exposición directa de los dispositivos de control a redes externas, como se menciona en Hajda, Jakuszewski y Ogonowski \cite{hajda2021security}.

\subsection{Selección del protocolo}\label{sec:protocolo}
\input{tablas/tabla_protocolos}
{A partir de la comparación de la Tabla~\ref{tab:protocolos}, se seleccionó PROFINET para la comunicación entre el PLC y la HMI, ya que ambos equipos lo soportan de forma nativa y se configura directamente en TIA Portal. Para la supervisión remota se seleccionó el protocolo S7, también nativo del PLC, mediante el cual Node-RED, en la Raspberry Pi, lee las variables del proceso a partir de sus direcciones de memoria; los datos se envían luego por HTTP a la API en AWS. De este modo, el PLC no requiere módulos de comunicación adicionales ni licencias de ejecución, y la Raspberry Pi concentra la conexión con los servicios externos.

En el primer corte se había propuesto Modbus TCP para conectar un gateway ESP32 con el PLC y MQTT, mediante un módulo SIM, para el envío de los datos a AWS \cite{cometa2025modbus,gonzalez2024awsesp32}. Esta propuesta se reemplazó por la arquitectura descrita, que se desarrolló y se verificó sobre el prototipo (Sección~\ref{sec:montaje_comunicaciones}).}

\subsection{Evidencia mínima de comunicación}
\input{tablas/tabla_prueba_comunicacion}
La Tabla~\ref{tab:evidencia_comunicacion} presenta la evidencia mínima de comunicación implementada durante el primer corte entre el PLC Siemens S7-1200 CPU 1214C y el panel HMI KTP700 Basic PN mediante una red Ethernet industrial, utilizando el protocolo PROFINET. Para esta comunicación se configuró la variable \texttt{CONTADOR\_HMI}, de tipo entero (INT), en la dirección \%MW2, permitiendo la transferencia de datos desde el PLC hacia la interfaz HMI para su monitoreo. Adicionalmente, la variable \texttt{C1\_Estado\_HMI} fue vinculada a una barra gráfica en la pantalla del HMI, de modo que el valor recibido desde el PLC se representó visualmente mediante el nivel de llenado de dicho elemento. La programación desarrollada permite comprobar el correcto intercambio de información entre ambos dispositivos, demostrando que los cambios realizados en el PLC son transmitidos y posteriormente visualizados de manera adecuada en la interfaz HMI. Con esto, se valida el funcionamiento de la comunicación industrial mediante PROFINET y la correcta asociación de las variables entre el controlador y el sistema de supervisión.
